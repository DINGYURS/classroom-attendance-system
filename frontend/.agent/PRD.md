# 产品需求文档（PRD）

## 一、产品概述

本产品面向高校课堂考勤场景，目标是替代传统人工点名方式，降低大班课程点名耗时，减少代签、漏签，并提升考勤数据沉淀与分析能力。系统采用“前端采集 + Java 后端业务编排 + Python 视觉识别服务”的端云协同模式：教师通过移动端或 PC 端上传课堂合照，系统自动完成人脸检测、身份比对和考勤结果生成；学生负责人脸底库录入、个人信息维护及考勤结果查询。

本项目当前仅包含两类账号角色：

- 教师
- 学生

管理员端不纳入本期建设范围。

## 二、项目目标

### 2.1 教师目标

- 上课前快速拍照完成点名
- 识别后立即查看缺勤、迟到、请假名单
- 对异常识别结果进行人工修正
- 可查看历史考勤、统计分析并导出报表

### 2.2 学生目标

- 学期初快速完成个人信息与人脸底库录入
- 平时可透明查看个人考勤历史与异常记录
- 支持更新个人信息、密码及人脸照片

## 三、角色范围与非目标

### 3.1 本期角色范围

- 教师端
- 学生端

### 3.2 本期不做

- 管理员端
- 前端上传前强制压缩图片

说明：为尽可能保留原始图像质量、提升 YOLO 人脸检测与后续识别效果，课堂点名和学生人脸采集场景默认采用原图上传策略。本期不将前端压缩作为默认方案，后续如需适配弱网环境，可再增加“可配置压缩开关”。

## 四、核心功能列表

### 4.1 学生端

1. **账号登录**
   - 学号 + 密码登录
   - 登录后按角色进入学生端页面

2. **人脸底库录入**
   - 支持调用摄像头拍照
   - 支持从相册选择照片
   - 前端提供圆形取景框、构图引导与预览确认
   - 系统需预检测，尽量保证仅包含单张清晰人脸
   - 后端调用算法服务提取特征，并对特征向量进行加密存储

3. **个人中心**
   - 查看头像、姓名、学号、行政班级、人脸录入状态
   - 修改姓名、密码
   - 更新人脸底库照片

4. **我的考勤**
   - 查看个人考勤历史
   - 支持按课程、学期、状态筛选
   - 展示出勤、迟到、请假、缺勤等状态
   - 展示个人出勤率与异常次数统计
   - 支持查看单条考勤详情

5. **异常记录提示**
   - 对缺勤、迟到等异常记录进行醒目标记
   - 可在个人端看到异常原因说明或教师修正后的最终状态

### 4.2 教师端

1. **教师工作台**
   - 展示课程总数、班级总数、学生覆盖数等基础概览
   - 展示近期课程、近期点名记录、异常提醒
   - 作为统计分析、预警信息的入口页

2. **课程与班级管理**
   - 创建、编辑、删除课程
   - 维护课程所属学期、课程简介
   - 关联教学班级与学生名单
   - 支持 Excel 导入学生名单
   - 支持模板说明、导入结果提示、错误反馈

3. **课程学生管理**
   - 查看课程下学生分页列表
   - 按学号、姓名、班级搜索
   - 查看学生详情与历史考勤轨迹
   - 支持名单导出

4. **发起点名（核心流程）**
   - 支持上传 1-3 张课堂照片，按左、中、右视角采集
   - 适配移动端摄像头拍照与本地相册选择
   - 默认保留原图上传，不做强制压缩
   - 提供上传进度、失败重试、清空重传
   - 发起点名会话后调用算法服务执行识别

5. **考勤结果确认**
   - 展示应到人数、实到人数、缺勤人数、迟到人数、请假人数
   - 展示已到名单、缺勤名单与异常名单
   - 支持人工修正考勤状态
   - 支持查看相似度、未匹配人数等识别信息

6. **历史点名档案**
   - 查看历史点名会话列表
   - 支持按课程、班级、日期范围筛选
   - 支持查看某次点名详情
   - 支持重新复核某次点名结果与导出历史报表

7. **数据统计分析**
   - 按课程、班级查看出勤率趋势
   - 提供折线图、柱状图、饼图等可视化图表（ECharts）
   - 支持查看课程整体出勤率、班级对比、学生异常排行
   - 展示近 7 天、近 30 天、学期维度统计结果

8. **缺勤预警**
   - 对累计缺勤超过阈值的学生进行标红提醒
   - 对频繁迟到学生进行预警提示
   - 教师工作台可查看预警名单和异常趋势
   - 通知能力先以站内提醒/页面提示为主

9. **报表导出**
   - 导出课程考勤明细表
   - 导出课程汇总统计表
   - 支持按搜索条件、课程、班级、时间范围导出 Excel

10. **识别结果可视化（增强功能）**
   - 在合照上绘制检测框
   - 展示识别姓名、相似度、未匹配框信息
   - 用于答辩展示与算法结果解释

### 4.3 算法与后台服务

1. **人脸检测与对齐**
   - 使用 YOLOv11 检测合照中的所有人脸
   - 返回检测框坐标、置信度等信息

2. **特征提取**
   - 使用 InsightFace 提取 512 维特征向量

3. **身份比对**
   - 由 Java 主导比对逻辑
   - 使用余弦相似度进行身份匹配
   - 阈值初始建议为 0.6，后续支持可配置化

4. **考勤会话管理**
   - 创建点名会话
   - 持久化识别结果与人工修正结果
   - 保存会话级统计数据，供历史查询与数据分析使用

5. **数据安全**
   - `feature_vector` 必须经过 AES 对称加密存储
   - 图片文件统一存储于对象存储服务
   - 接口遵循统一鉴权与统一响应格式

## 七、界面设计要求

### 7.1 整体风格

- 风格定位：简洁、学术、偏专业后台
- 主色调：蓝、白、灰
- 组件库：Element Plus
- 布局要求：教师端偏管理后台，学生端偏移动端轻应用

### 7.2 关键页面要求

1. **教师发起点名页**
   - 顶部展示课程名称、班级信息、应到人数
   - 中部展示左、中、右三个上传卡片
   - 底部有明显的“开始识别”按钮和状态进度

2. **教师结果确认页**
   - 顶部展示缺勤/实到/迟到/请假汇总卡片
   - 中部展示学生结果卡片列表
   - 支持按“全部 / 异常”切换查看
   - 每个学生支持状态修正

3. **教师统计分析页**
   - 顶部展示筛选器：课程、班级、时间范围
   - 中部展示折线图、饼图、柱状图
   - 底部展示异常学生排行和课程统计表格

4. **学生人脸采集页**
   - 以圆形取景框为中心视觉焦点
   - 明确提示光线、角度、清晰度要求
   - 支持拍照和相册导入双入口

5. **学生我的考勤页**
   - 展示个人出勤率、缺勤次数、迟到次数
   - 支持按课程和时间筛选
   - 历史记录展示尽量移动端友好

## 八、技术栈建议

- **前端**：Vue 3（`<script setup>`）+ Element Plus + Axios + ECharts + Tailwind CSS
- **后端**：Spring Boot 3 + MyBatis + Hutool
- **算法微服务**：Python 3.11 + FastAPI + PyTorch + YOLOv11 + InsightFace
- **结构化数据**：MySQL 8.0
- **非结构化数据**：MinIO
- **部署运维**：Docker + Docker Compose + Nginx

说明：前端暂不采用默认压缩上传策略，优先保证识别输入质量。

## 九、代码风格与架构模式

### 9.1 架构模式

- **Java Core**：负责认证鉴权、业务逻辑、数据库读写、会话管理、特征比对、加密解密
- **Python Worker**：无状态服务，只负责图像处理、目标检测、特征提取与结构化结果返回
- **Vue Frontend**：负责数据采集、流程引导、结果展示、统计分析与交互修正

### 9.2 代码风格

- **Java**：遵循《阿里巴巴 Java 开发手册》，业务逻辑下沉到 Service 层
- **Python**：遵循 PEP8，使用 Type Hints
- **Vue**：使用 Composition API 和 `<script setup>`，公共逻辑优先抽离为组合式函数

### 9.3 API 规范

- 遵循 RESTful 风格
- 统一响应结构：`{ code, message, data }`
- 涉及文件上传时统一走对象存储接口
- 涉及长耗时识别任务时需要前端展示清晰的加载态与错误提示
